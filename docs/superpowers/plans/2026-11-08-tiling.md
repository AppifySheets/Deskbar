# Tiling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A workspace can be tiled from its row menu: on the desktop you are on, its windows fill each screen as a grid with a gap, and the grid keeps itself tidy. Deskbar Pro only.

**Architecture:** Everything that decides lives in `Deskbar.Core/Tiling` as pure code, unit-tested: the grid arithmetic, the per-screen slot board, the settled-move rule and a `Tiler` coordinator that reacts to window events. Everything that touches Windows sits behind one new interface, `ITileSurface`, implemented in `Deskbar.Windows/Tiling/TileSurface.cs`: screens and work areas, which windows can tile, visible frames, placing, rounded corners, and a scoped LOCATIONCHANGE hook that reports when a window has settled after a move. The App wires the two together, adds the menu item and the Manage setting.

**Tech Stack:** C# / .NET 10, WPF, System.Reactive, CSharpFunctionalExtensions, xUnit.

**Spec:** `docs/superpowers/specs/2026-11-08-tiling-design.md`. Read it before any task.

## Global Constraints

- Follow Petre's C# rules (global CLAUDE.md): no `private` keyword, expression bodies, `var`, readonly collections, immutable records, setters in the order none > private init > private set > init > set, lambdas over loops, `Result`/`Result<T>`/`Maybe<T>` from CSharpFunctionalExtensions for expected failures.
- Ample comments that carry the reasoning, as the rest of the codebase does. Quote Petre where a decision is his.
- All geometry in physical pixels. `WindowRect` (`Deskbar.Core/Domain/MonitorMove.cs`) is the rectangle type; Right and Bottom are exclusive.
- Default gap 8 at 100% scaling, scaled by each monitor's DPI (`gap * dpi / 96`, rounded).
- Grid: columns = ceil(sqrt(n)); column i of the remaining takes floor(remaining windows / remaining columns); columns equal width, rows equal height; integer remainders go to the last column and the last row.
- Gate: tiling acts only when `AppState.ExperimentalTiling` is on AND the workspace is tiled AND `Entitlement.Current.IsPro`. `untile` always works.
- Experimental and off by default (Petre: "disabled by default, until i have tested it well"). While off: no tiling, no LOCATIONCHANGE hook, no tiling item in the row menu, `tile` refuses.
- Only the desktop being looked at is tiled. Never un-maximize, move or restore a window on another desktop.
- Only windows that LIVE on the workspace tile: `WorkspaceManager.WorkspaceOf(window)` equals the workspace. Borrowed and pinned windows float.
- Re-tiles use `SWP_NOZORDER | SWP_NOACTIVATE`. Never hide or cloak a window.
- No code copied from komorebi or AltSnap.
- Before the PR: `dotnet build Deskbar.sln -c Release -warnaserror` and `dotnet test Deskbar.sln --filter "Category!=Integration"` both green. The PR gets a `## Release notes` section written for users.
- Run the app for live checks with `DESKBAR_APPDATA=%TEMP%\deskbar-dev` and `DESKBAR_PRO=1` (the developer override only works with the scratch root).

## Review Focus

1. An app whose minimum size is larger than its slot: it settles at its own size; Deskbar places it once per re-tile and does not loop. (Task 4, `A_window_that_will_not_shrink_is_placed_once`)
2. A window that dies between the decision and the move: `Place` fails, the grid drops it and the rest still tile. (Task 4, `A_window_closing_mid_retile_leaves_the_rest_tiled`)
3. A screen unplugged while tiled: its windows rejoin whichever screen they end up on. (Task 4, `Windows_from_a_screen_that_went_away_join_the_screen_they_are_on`)
4. A maximized window that closes: its kept slot is freed and the grid closes up. (Task 4, `A_maximized_window_that_closes_frees_its_slot`)
5. Windows opened on a tiled workspace while you were elsewhere: arriving re-tiles them in. (Task 4, `Arriving_at_a_tiled_workspace_tiles_what_changed_while_away`)

- [ ] **Step 3: Implement `Tiler`**

Subscribes to `monitor.Events`, `desktops.CurrentChanged`, `surface.Settled`, `surface.ScreensChanged`; all handlers wrapped so one exception cannot end the subscription (see the Rx note at `WorkspaceManager.cs` ~line 382). The board is rebuilt from `TileBoard.FirstFill` when tiling turns on and kept in step afterwards. A re-tile computes `GridLayout.Arrange(screen.WorkArea, count, gap * dpi / 96)` per screen, skips maximized windows (their slot still counts), and calls `Place` only for windows whose frame differs from their slot. After each `Place` the Tiler reads `VisibleFrameOf` back and keeps it as that window's accepted frame (the slot itself, or the size an app insisted on). That is the self-move guard: a `Settled` whose frame equals the accepted frame does nothing. Any other `Settled` first checks `WorkspaceOf` (a window the bar moved to another workspace just leaves), then goes through `SettledMove.Decide`. `RoundCorners` once per window as it joins. `Watch` is given the set of tiled windows whenever it changes, and the empty set off a tiled desktop. Trace one line per re-tile only when the layout changed: `tile: <workspace> screen <n>: <hwnd>@<rect> ...`.
