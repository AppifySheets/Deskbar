# Subtasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A task can be a subtask of another, and a Claude session on any task of such a family is briefed on the parent, the siblings and their sessions (with transcript paths), so Petre can add a subtask with only a title.

**Architecture:** A `ParentId` link on `TaskItem` with its rules in `TaskBoard` (pure, tested). One pure text builder, `SessionBriefing.Family`, fed with transcript paths the app resolves, printed by the `task join` reply, the SessionStart briefing and `task family`. The bar and the tasks window gain "Add subtask…", a parent chip on their add boxes and a breadcrumb on lines, after Petre sees a mockup.

**Tech Stack:** C# / .NET 10, WPF, CSharpFunctionalExtensions, xUnit.

**Spec:** `docs/superpowers/specs/2026-11-24-subtasks-design.md`

## Global Constraints

- One level: a subtask cannot have subtasks, and a task with subtasks cannot become one.
- Lines keep their place: `TaskBoard.Pile` and `Group` are unchanged by a parent link.
- Bounds for the family text: titles cut at 80, descriptions at 200, at most the last 3 unsettled comments each cut at 200, at most 10 siblings or subtasks listed (then "and N more: deskbar.cmd task family --session <sid>"), at most 3 sessions per task (live first, then latest joined), the whole block cut at 4,000 characters with the same pointer.
- Text a session reads: plain sentences, no em dashes, no names ("the user"), commands spelt out with `deskbar.cmd`, free text on stdin (`-`).
- Every new `task` form is in `ControlUsage` (a test fails otherwise).
- Every new stored field is optional and read tolerantly; a file without it loads as before.
- Comments in code carry the reasoning, as the rest of this codebase does; C# style per the user's CLAUDE.md (expression bodies, immutability, `var`, no `private` keyword).
- Before the PR: `dotnet build Deskbar.sln -c Release -warnaserror` and `dotnet test Deskbar.sln --filter "Category!=Integration"`. Windows tests only through `pwsh scripts/test-hidden.ps1`, never on Petre's desktop.

## Review Focus

1. A parent deleted while its subtasks are open: subtasks become plain tasks, nothing dangles, the briefing says nothing about a parent. (Task 2 test `Delete_FreesSubtasks`.)
2. A hand-edited tasks.json whose `parent` names a missing task, the task itself, or a chain (A under B under C): loads without throwing; a missing parent reads as no parent in `Family`; a chain is shown one level only. (Task 1 test `Load_ParentNamingNothing_KeepsTask`, Task 2 test `Family_ParentMissing_IsNone`.)
3. A family big enough to pass Claude Code's 10,000 characters for hook context: twenty subtasks each with five sessions and 300-character titles stay under 4,000 characters of family text. (Task 3 test `Family_LargeFamily_IsBounded`.)
4. Free text with quotes, `&`, `|`, `<`, `>` in a subtask title made by a session: goes on stdin and arrives whole. (Task 4 test `SessionSubtask_TitleFromStdin_KeepsSpecialCharacters`.)
5. A session on a subtask whose parent is closed: still briefed on the parent, marked "(closed)". (Task 3 test `Family_ClosedParent_IsDescribed`.)
